# nos-log — Log Collection Daemon

Collects structured log entries pushed by every other component process into a bounded, disk-backed buffer, queryable by `nos-cli` (binary `nos-logd`, a single fixed process — supervised the same way as `nos-interfaced`, since log collection has no per-config-object scope to spawn one instance per).

## Scope

Every other daemon forwards its own `tracing` events here over one long-lived `LogRequest::Push` connection, via the shared `nos-log-client` crate (`log-client/`). That crate depends only on `nos-proto`, so it doesn't breach the root `CLAUDE.md`'s star dependency graph the way sharing a component crate would. `nos-logd` itself never forwards its own logs anywhere — it's the foundation, and logs to stdout only via a plain `tracing_subscriber::fmt::init()` (so the syslog export's own state lines are in `docker logs`, never in `show log`, and an export error can't loop back into the export).

It does read the config, for one purpose: **remote syslog export** (#71, `Config.logging.syslog`). `--watchdog-socket` (the watchdog hands it over at spawn) resolves `nos-configd` and each collector's `nos-ribd` — **in a background task** (`syslog::reconcile::run`), so startup and the IPC server never wait on `nos-configd` (every other daemon's forwarder needs `nos-logd` up first).

The buffer is bounded (`--capacity`, default 10,000 entries, oldest evicted first) and mirrored to disk (`--log-store-path`, default `/var/lib/nos/logd/entries.jsonl`) so recent history survives a restart. Ring + persist-queue memory is capped at 20 MiB (`store::MAX_MEMORY_BYTES`, not configurable; a cap on those, not on RSS: the watchdog sets `MALLOC_ARENA_MAX=1` for glibc, #756; startup/compaction read only the last 20 MiB of the file); entries are clamped to 64 KiB (`store::clamp_entry`) and the file compacts past 40 MiB too (#640): 16 MiB of ring buffer (evicting oldest first, on top of `--capacity`) plus a 4 MiB byte budget on the queue feeding the persistence task, past which entries are still kept in the ring but no longer queued for disk — added after a logging hot loop in another daemon grew `nos-logd` to ~14 GB through the previously unbounded persistence queue. It is the one daemon in this system with disk-backed state purely for its own sake, rather than for cross-restart identity like `nos-ribd`'s table registry.

There is an external query API: `server.rs` serves `nos_proto::log::{LogRequest, LogEvent}` for `nos-cli`'s `show log`/`show log --follow` commands (see `docs/architecture/endpoint-broker.md` for how `nos-cli` finds this instance's socket — `ServiceRef::Log`, resolved directly by the watchdog like `ServiceRef::Config`/`Interfaces`, since there's exactly one instance). Every other daemon, by contrast, is handed this socket directly via `--log-socket` at spawn time rather than resolving it through the broker — see `docs/architecture/supervision.md`.

## Modules

| Module | Role |
|--------|------|
| `main.rs` | Arg parsing (`--listen-socket` default `/run/nos/log.sock`, `--log-store-path`, `--capacity`, `--watchdog-socket`), loads persisted entries to seed the buffer, SIGINT+SIGTERM shutdown wait (then triggers the persist drain, 5s from the signal, #679), spawns `persistence::run`, `server::start` and `syslog::reconcile::run` sharing one `LogStore` |
| `store.rs` | `LogStore` — cheap-`Clone` handle (like `nos-config`'s `ConfigStore`) over a bounded `VecDeque<LogEntry>`, a `tokio::sync::broadcast::Sender` for live `Tail` subscribers, and the channel feeding the persistence task. `record` (append + evict + broadcast + forward to disk), `snapshot` (filtered, capped read), `subscribe` (a fresh broadcast receiver) |
| `persistence.rs` | `load_recent` (seeds the buffer at startup, oldest-first, tolerating a missing or partially-malformed file) and `run` (the background task, which on its `watch` drain trigger closes its own receiver and flushes the queue, appending one JSON line per entry, compacting back down to `--capacity` lines via the same temp-file-then-rename atomic pattern as `nos-config`'s `persistence::save_to_disk` once the file grows past twice that) |
| `syslog/render.rs` | Pure: one `LogEntry` → one RFC 5424 message (`<PRI>1 TIMESTAMP HOST APP PROCID - [timeQuality …] BOM+MSG`), header fields cut to PRINTUSASCII and the RFC's limits, truncation on a UTF-8 boundary, the severity map and level filter. Entry fields go in MSG as ` k=v`: a private SD element needs an IANA enterprise number nos doesn't have |
| `syslog/sink.rs` | One task per collector with its own `LogStore::subscribe()` receiver (a slow collector lags only itself; `Lagged(n)` counts drops, nothing blocks `Push`). UDP: one datagram, 1180 octets max (RFC 5426). TCP/TLS: RFC 6587/5425 octet counting, 8192 max (`serve`, generic over the stream; TLS is `nos_pki::syslog::Connector` over the connected socket — trust anchor or fingerprint, `allow_tls12`; a handshake failure is `tls handshake: …`, the connect log carries `version`/`kx`/`suite`, a TLS 1.2 session also warns `syslog tls12 classical key exchange`; stopping sends `close_notify`), a read on the half-duplex connection notices the collector closing, reconnect on a fixed 1s with no backfill (the receiver is created only once connected). `routing_table` → `RibRequest::GetVrfName` → `SO_BINDTODEVICE`. Logs state transitions only, plus a minute drop summary — never a line per failed send |
| `syslog/reconcile.rs` | `Get` + `SubscribeDiff([Logging, Hostname])`, one sink per collector; a changed collector or hostname restarts its sink (pure `plan`) |
| `syslog/client.rs` | The broker / `nos-configd` / `nos-ribd` calls the export needs, reimplemented here per the star dependency graph |
| `server.rs` | Binds `--listen-socket` and serves `LogRequest::Push` (records, no reply — the connection a forwarding daemon holds open for its whole lifetime), `GetLogs` (one-shot filtered/capped snapshot), and `Tail` (one initial snapshot reply, then streams new matching entries from the store's broadcast channel until the client disconnects) |

## Wire protocol

`nos_proto::log`'s `LogRequest`/`LogEvent` share one socket for three shapes, distinguished by request variant rather than three separate listeners: `Push(LogEntry)` (fire-and-forget, from every other daemon), `GetLogs { source, limit }` and `Tail { source }` (`nos-cli`'s snapshot and live-tail queries respectively). See `docs/ipc-protocols.md` for the exact types.

Memory profiling (#757): optional `dhat-heap` feature (`--profile-memory-out`), `tests/resident.rs` counting-allocator bound, `nos-e2e logd-mem` lab load, phase `logd-memory` (manual group `logd-memory-lab`) — see the logging page.
