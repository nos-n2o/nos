# nos-rest — REST API daemon (`nos-restd`)

An HTTP+JSON management API for the whole system: every `nos-cli` `show` query and the full transaction/config-editing surface. One process per `RoutingTable` that has `rest-api` pinned to it, listening on **one configured address inside that table's VRF**. **Every request needs a TLS client certificate** for a user in `Config.users` (see `auth.rs`, `login.rs` and root `CLAUDE.md`'s "User authentication"); the VRF and pinned address are a second boundary, so still pin it to a management address. The listener is HTTPS only — TLS 1.3 with post-quantum key exchange (hybrid `X25519MLKEM768`, nothing else), HTTP/2 or HTTP/1.1 by ALPN.

## Pinning and supervision

`RoutingTable.rest_api: Option<RestApi { address, port }>` (`set routing-table <t> rest-api address <ip> [port <n>]`). `nos-watchdogd` runs `nos-restd --table <name>` for every table that has it set, via the same `instances::manage` as `nos-ribd`/`nos-bgpd`/`nos-ospfd`, with one addition: `Managed.claim_label`. The other families spawn a process per section; this one is *opt-in per table*, and a field flip on an existing table is a `Modified` diff (a no-op for the others), so the watchdog keys on the `rest-api` `FieldDiff` (`nos_proto::diff::routing_table::REST_API_LABEL`): a value other than `"unset"` spawns, `"unset"`/removal stops. It has no IPC query listener, so `Managed.endpoint` is `None` (no `--listen-socket`, no registry entry).

## Allocator

`nos-restd` uses `tikv-jemallocator` as its global allocator (not under `dhat-heap`): glibc malloc kept freed pages in its heaps under REST churn (RSS 55 -> 159 MB at flat live heap, #798/#801). Needs `make` in the Dockerfile builder stage.

## Errors (`error.rs`)

Every error is an RFC 9457 problem document, `Content-Type: application/problem+json`: `{"type":"about:blank","title":<reason phrase>,"status":<HTTP status>,"detail":<message>}` (`ErrorBody`; `instance` is omitted, since a handler can't see the URI). Handlers return `ApiError`, whose variant picks the status (400/401/404/412/422/503/502). Errors the framework raises itself — unknown route 404, 405 (its `Allow` header is preserved), extractor rejections — are re-rendered by `problem_for_framework_errors`, the outermost layer in `api::router`; it leaves problems and non-error responses (SSE included) alone. `openapi::document` re-keys every `ErrorBody` response to `application/problem+json`, so the `#[utoipa::path]` annotations just say `body = ErrorBody`. Never build an error response by hand.

- 502/503 `detail` is generic by construction (`ApiError::into_response` logs the specific string with `warn!`): never expect a path or `Debug` dump in an `ApiError` string to reach a client, and never put one in a 200 body either (#408).

## Testing

`tests/api.rs` drives the real router (via `tower::ServiceExt::oneshot`, with the `PeerUser` a verified certificate would produce injected as a request extension) against a **real** `nos-config` `ConfigStore` behind its own IPC server — so the path-set semantics tested are the shipped ones — plus a fake broker (which stands in for the CA on `RestLogin`/`RestRenew`) and fake `nos-ribd`. The pooling tests count the connections a fake daemon accepts (ten requests → one; a daemon that hangs up after every reply → retried, not an error). The `over_tls` module runs the real `listen::serve` on 127.0.0.1 with a real REST CA and a hyper HTTP/2 client: 20 concurrent requests over one connection, a certificate for an unknown user or none at all → 401, login without a certificate, a foreign CA's certificate refused. The VRF bind needs `CAP_NET_RAW`, so only `nos-e2e rest` covers that.

## Rules that bite

- **Authentication** (`auth.rs`, `login.rs`): every route except `POST /v1/login` needs a client certificate from the REST CA (`rest-ca.crt`, distributed out of band, never served). Login forwards to the watchdog (`WatchdogRequest::RestLogin`, `restd` only; renew is `RestRenew`). One login attempt at a time per username (`LoginGate`), a failure costs 1s, 5 failures in 60s from one source address on one username give `429` with `Retry-After` (keyed `(address, user)`: a remote attacker can't lock the real user out; one behind the user's NAT address still can); at most 8 logins in flight overall (`429` beyond), and the watchdog bounds argon2 itself (#381).
- **`client_auth` is the last `.layer(..)` in `api::router`**, so it wraps Swagger UI, `/openapi.json` and the SSE stream. The user must still exist in the running config (one pooled `UserExists` probe per request, #755), so a deleted user is refused on the next request: no verified user is `401`, unreachable `nos-configd` is `503` (fail closed). An open SSE stream is authenticated at connect time only.
- **Transport** (`listen.rs`, `tls.rs`, `ipc.rs`): TLS 1.3, hybrid `X25519MLKEM768` only, HTTP/2 or HTTP/1.1 by ALPN, handshake timeout 5s, graceful shutdown capped at 2s. The server certificate comes from `IssueRestServerCert` (IP SAN from config, never from the CSR). IPC connections are pooled (`Daemons::call`): relies on every daemon server answering a plain request with exactly one event and reading the next request on the same connection; streaming replies (`LogRequest::Tail`) use `open_stream`. Only "dead before any reply" is retried, so a received request is never sent twice.
- **Limits:** request bodies 2 MiB (axum default, `413`; a list `PUT` replaces the list, so big sets go in as whole-subsection PUTs, #754), 256 connections (`listen::MAX_CONNECTIONS`, refused before the handshake), 30s request (`408`), 20s per IPC call (`504`, not retried), handshake-failure logs rate-limited per peer (`ratelimit.rs`); details in the internals page.
- **Pinning:** `RoutingTable.rest_api` (`RestApi { address, port }`) spawns `nos-restd --table <name>` through `instances::manage` with `Managed.claim_label` keyed on the `rest-api` `FieldDiff` (`REST_API_LABEL`); no IPC listener, `Managed.endpoint` is `None`.
- **Listening** converges every 1s: VRF name from `nos-ribd` (`GetVrfName`), bind with `SO_BINDTODEVICE`, `EADDRNOTAVAIL` retried and logged once per change; a recreated VRF (ifindex change) rebinds; a `nos-configd` read failure keeps the listener.
- **Endpoints:** the config tree is the URL tree (`<path>` grammar in `nos_proto::config_path`; handlers split the raw URI path before percent-decoding; `diff` and `commit` are reserved segments). Every transaction reply carries a strong `ETag` (the transaction generation, quoted decimal); `If-Match` (`*` or a tag list, strong) is a store-side compare-and-set (`if_match: Option<Vec<u64>>`, mismatch `ConfigError::PreconditionFailed` is 412, a refused commit keeps the transaction; any `If-Match` on a missing transaction is 412, also on `GET`, where it runs before `If-None-Match`), `If-None-Match` (list, weak) gives 304. Show endpoints report a per-instance "not running", an unreachable daemon is `503`; `POST /config/save` is never implied by a commit. Route table: `docs/openapi.json`.
- **Secrets** (#507): `GET /v1/config` and every transaction reply go through `Config::redacted()` (`tx::redacted_snapshot`/`subsection`); a new route returning config must do the same. The mask round trip is in `nos-configd`.
- **Errors** (`error.rs`): RFC 9457 `application/problem+json` via `ApiError`; never build an error response by hand.
- **OpenAPI** (`openapi.rs`): show and transaction-root routes are `#[utoipa::path]` plus a `routes!` line; config-tree paths are generated from the `Config` schema. Any change fails `tests/openapi_snapshot.rs` until `make docs-fix` rewrites `docs/openapi.json`.

Details: [internals](../docs/internals/rest.md) (authentication and login, transport, listening, endpoint catalogue and concurrency, OpenAPI), [REST API guide](../docs/api.md), [`docs/openapi.json`](../docs/openapi.json).
