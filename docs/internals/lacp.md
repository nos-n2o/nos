# LACP internals

How `nos-lacp` is built, moved from `lacp/CLAUDE.md` (#264) so the always-loaded file keeps only rules and pitfalls. The rules to respect when editing the crate are in [`lacp/CLAUDE.md`](../../lacp/CLAUDE.md).

## The state machines (802.1AX §6.4, simplified for this crate's model)

Each currently-configured member port gets its own `link::run` task (spawned/stopped by `aggregate::AggregateManager`, one per `Lacp`-mode `PortAggregate`, mirroring `ospf::link::LinkManager`), running three interacting machines:

- **recordPDU match and update_Selected** (`link::partner_matches_actor`, §6.4.9, after Linux `bond_3ad.c` `__record_pdu`/`__choose_matched`): the partner's Synchronization/Collecting only count when its Partner block describes our current Actor (port, port priority, system, system priority, key, Aggregation bit); otherwise the stored partner loses Sync, the mux sees `synchronized=false`, and `lacp partner view mismatch` is logged once per match-to-mismatch transition (`lacp lacpdu received` carries `partner_view_matches`). An Individual partner (Aggregation clear) skips the match. A change of the partner's identity tuple between PDUs drops the mux out of Collecting/Distributing at once; selection then re-runs from the new observation.
- **Receive Machine** (`receive_machine.rs`, §6.4.12): `Expired`/`Defaulted`/`Current`. Simplified from the full standard's six states, but `Expired` keeps the learned partner and the port's selection (only the partner's Synchronization/Collecting clear and its timeout turns short, as Linux `bond_3ad.c` does), so one missed LACPDU does not detach the member. `Defaulted` records the administrative default partner (system all-zero, key 1, port 1, priorities `0xffff`/`0xff`, state 0: Linux `ad_initialize_port`'s `partner_admin`) and the port stops being selectable (`PortObservation::selectable`: Current, or Expired with a learned partner). `Initialize`/`PortDisabled`/`LacpDisabled` collapse into the task's own startup (`Event::Started`, entered once, never revisited), since a `link::run` task exists only while its port is a configured, running aggregate member in the first place; there's no separate "port administratively disabled but task still alive" state to model. `Current`'s own timeout duration (`Current_While_Timer`) follows *our own* configured `lacp-rate` (Short 3s for `fast`, Long 90s for `slow`) — 802.1AX §6.4.12: the timer measures how long *we* tolerate silence from the partner, and our advertised `LACP_Timeout` bit is what tells the partner how fast to send.
- **Periodic Transmission Machine** (`periodic_tx_machine.rs`, §6.4.13): `interval_for(receive_state, actor_active, partner_active, partner_wants_fast) -> Option<Duration>`. `None` is **NO_PERIODIC**: both ends Passive (no partner heard counts as Passive), so `link::TxState` transmits nothing at all, periodic or NTT-driven, until a received LACPDU carries Activity; logged as `lacp periodic transmission machine transitioned … no_periodic=`. A Passive port with an Active partner still sends periodically and answers. Otherwise: always Fast (1s) while there's no live partner (`Expired`/`Defaulted`) — fast-until-heard matters because a port whose link comes up after its first send would otherwise sit silent for a whole Slow interval. Once `Current`, the interval follows the **partner's** advertised `LACP_Timeout` bit (Fast 1s if it asked for short timeouts, else Slow 30s), per the standard: the partner's timeout bit says how often *it* expects to hear from us.
- **Transmit on change, not on receipt** (`link::needs_transmit`, 802.1AX's NTT): an event-driven send happens only if the PDU we'd advertise differs from the last one sent. Replying to *every* received LACPDU made two peers ping-pong at wire speed; with this they settle as soon as their states agree.
- **Mux Machine** (`mux_machine.rs`, §6.4.15/Figure 6-11): `Detached`/`Waiting`/`Attached`/`Collecting`/`Distributing`, including a real (if short, `AGGREGATE_WAIT_TIME` = 2s) `Waiting` state — 802.1AX's own aggregate-wait-time settling period, kept faithful to spec despite this crate having no dynamic cross-aggregate reassignment to actually protect against. **`Distributing` is the only state in which a port belongs in the active-member set pushed to `nos-interfaced`.**

Each machine is a pure `step(state, event) -> (state, Action)` function, unit-tested directly per transition — no I/O, mirroring `ospf_common::neighbor`'s own pure-step precedent. `link.rs` is the impure, I/O-owning caller: owns the `socket::LacpSocket`, drives the three machines off real timer ticks and real received LACPDUs, and reports every observable change (Receive state → `current`, last-recorded partner identity, Mux state) into a shared map (`link::PortObservation`) that `aggregate::AggregateManager`'s own background task consumes.

**Internal state is never `nos_proto::lacp`'s wire types directly** (`ReceiveState`/`MuxState` in this crate vs. `nos_proto::LacpReceiveState`/`LacpMuxState`) — same convention as `ospf::link::InterfaceState` vs. `nos_proto::LinkInterfaceState`: this crate's own state isn't necessarily wire-serializable forever.

### `lacp-rate` (LACP fast)

`PortAggregate.lacp_rate` (`LacpRate::{Slow (default), Fast}`, `set port-aggregate <name> lacp-rate fast|slow`) is the one CLI-exposed protocol knob. It drives two things on every member port, both from the same value (`link::LinkConfig.rate`):

- the **TIMEOUT bit** we advertise in Actor_State (`link::actor_state_byte`) — set means "send to me every 1s";
- **our own** `Current_While_Timer` duration (3s vs 90s, `receive_machine::Event::LacpduReceived { we_advertise_short_timeout }`).

Our own *transmit* rate is deliberately **not** driven by our own `lacp-rate` — it follows what the partner asks for (see above). So two peers with different rates interoperate: each sends at the rate the other requested and tolerates silence for the duration matching its own request. A rate change re-runs `aggregate::AggregateManager::reconcile`, which restarts member links (a rate can't be swapped into a live `link::run`).

## Selection Logic — deliberately config-scoped (§6.4.14, narrowed)

`selection.rs` never discovers aggregate membership from the wire the way real 802.1AX Selection Logic does. `PortAggregate` membership is already a config-defined, operator-fixed reference (`Interface.port_aggregate`), and the kernel bond device is already fixed by `nos-interfaced` independent of LACP — so `select` only ever compares ports already belonging to the *same configured* aggregate, and its job is to confirm the wire agrees with what was configured (every `Current` port reporting a consistent partner system-id + key), not to replace config-driven membership with wire-driven discovery. A `Current` port whose partner identity disagrees with the aggregate's majority is excluded — a basic split-detection, tie broken by input order for determinism. This is the deliberate, permanent v1 design, not a temporary cut.

Re-run by `aggregate::AggregateManager`'s background `selection_loop` task every time any port's observation changes (edge-triggered via a `tokio::sync::Notify`, not polled) — its outcome both feeds each port's own `mux_machine::Event::SelectionChanged` (via a per-port `tokio::sync::watch` channel) and, together with each port's live `MuxState`, recomputes the `Distributing`-state subset pushed to `nos-interfaced`.

## Actor identity — no new persisted registry

Unlike `interface::driver::port_aggregate_registry`'s YAML-backed bond-id allocator, LACP's Actor identity needs no persisted file:

- **System ID**: a locally-administered unicast MAC derived (FNV-1a) from the machine's hostname and machine-id (`aggregate::local_system_id`), fixed for the life of the process — deliberately **not** derived from any member port. Bonding rewrites its slaves' MACs (the first slave enslaved lends its MAC to the bond, every other slave takes it over), so a port-derived ID changed whenever enslavement order did, which restarted every link in a loop. `ponytail:` two machines sharing both hostname and machine-id would collide; upgrade path is a persisted random id file. **Overridable per aggregate** with `PortAggregate.lacp_system_id` (`set port-aggregate <n> lacp-system-id <mac>`): `AggregateManager::reconcile` takes it as `Option<[u8; 6]>` and, like a `lacp-rate` change, restarts every member link when the effective id changes. Its purpose is EVPN multi-homing — two PEs sharing an ESI must present the same actor to the customer device, or it can't bundle its links across them — see `docs/protocols/evpn-vxlan.md`.
- **Loopback**: a received LACPDU whose actor system id equals ours (priority ignored) is a looped link, e.g. two members of one host cabled together. It is dropped before recordPDU: no partner, no timers touched, so the port ages into `Defaulted` and never reaches `Distributing`. Logged once as `lacp loopback detected` (`warn`), then at `debug`. EVPN multi-homing PEs share a system id but are never cabled to each other.
- **Key**: assigned sequentially in-process, per aggregate name, the first time `reconcile.rs` sees it — not persisted (only needs to differ between simultaneously-active aggregates on this instance).
- **System/Port Priority**: `PortAggregate.lacp_system_priority` / `Interface.lacp_port_priority` (`Option<u16>`, `None` = `aggregate::DEFAULT_PRIORITY` = `32768`, the 802.1AX default). `AggregateManager::reconcile` takes the system priority (a change restarts every member, like `lacp-rate`/system id) and `(name, port_priority)` per member (a change restarts only that member; its `link::run` task owns the value for its lifetime). Both go out in the Actor Information TLV and the partner's are shown in `show lacp`. **Port Number** (#689): see below.
- **Port Number**: 802.1AX §6.3.4 wants a unique, non-zero 16-bit value per system, and the system ID is shared by all aggregates, so `aggregate::PortNumbers` is one daemon-wide allocator (created in `reconcile::run`, shared by every `AggregateManager`).
    - Lowest free number in `1..=65535`; never 0 and never the ifindex (which can be 0 after masking or collide).
    - Sticky while the member stays configured: adding or removing another member, or a rate/priority restart, never changes it. Freed only when the member leaves its aggregate or the aggregate is removed.
    - Not persisted: `nos-lacpd` restarts renumber from scratch. With all 65535 taken a member is skipped with a `lacp port numbers exhausted` warning.

- **LACP v2 schema (#892, no behaviour yet)**: `PortAggregate.lacp_version` (`LacpVersion`, default `DEFAULT_LACP_VERSION` = `V2`), `lacp_port_algorithm` (`LacpPortAlgorithm`, default `DEFAULT_LACP_PORT_ALGORITHM` = `Unspecified`), `lacp_conversation_map` (`Vec<ConversationRange>`, key `first`), `Interface.lacp_link_number`. Both defaults are single constants in `proto/src/schema/port_aggregate.rs`: a no-go on the dataplane flips the version one with one line. `valid_port_aggregates` rejects bad ranges/overlaps/non-members, a map or algorithm on a non-`lacp` or `lacp-version 1` aggregate or with `unspecified`, and zero or duplicate link numbers. `LacpPortStatus.partner_version`/`partner_port_algorithm` and `PortAggregateLacpSummary.version`/`port_algorithm`/`agreement`/`conversations_per_link` are appended last on the wire; `aggregate.rs::summary` fills neutral values until #894. `show lacp` prints the extra `version 2, algorithm …, agreement …` line only for version 2.
- **Mode**: `Interface.lacp_mode` (`Active` default, `Passive`) sets Actor_State.LACP_Activity (`link::actor_state_byte`). `AggregateManager::reconcile` takes it per member alongside the port priority; a change restarts only that member. Two Passive ends never leave Defaulted and so never reach `Distributing` (permanent, standard behaviour).

- **min-links**: `PortAggregate.min_links` (`u16`, default 1, 0 ≡ 1). A pure selection-side policy: `AggregateManager` holds it in an `AtomicU16` read by `selection_loop` (a change restarts no link; `reconcile` just wakes the loop), and `selection_loop` clears the *pushed* active set when `active_set(..).len() < min_links` (`min_links_met`), logging `lacp min-links not met, bond emptied` once per transition. `selected`, each port's Mux machine and the LACPDU flags are untouched, so ports keep negotiating and the bond refills as soon as the count is met. `reconcile.rs` warns when `min_links` exceeds the configured member count (no commit-time check: membership lives on `Interface`). `show lacp` carries `min_links`/`min_links_met`.
- **Unsupported LACPDU version (#688)**: `decode` takes version 1 and 2 PDUs of 110 bytes or more (v2 only appends TLVs). Any other Version byte is dropped without a log line and counted in `PortObservation::unsupported_version_pdus` (after the 10/s RX budget). Read it per port in `show lacp` (`unsupported-version PDUs <n>`) or `GET /v1/lacp` (`unsupported_version_pdus`). It lives in memory: it restarts at 0 with the port's link task (member re-added, or `nos-lacpd` restart). We still send version 1 only.
- **Individual partner**: `PortObservation::partner_individual()` (the partner's last Actor_State has Aggregation clear). `selection::select` drops such ports before counting partner groups, so an Individual port is neither selected nor a voter; its Mux machine stays `Detached`/`Waiting` through the normal `SelectionChanged` path. Shown as `individual` in `show lacp`. Our own Aggregation bit stays 1 (only configured members run LACP).

`lacp-rate`, `lacp-system-id`, the two priorities, `lacp-mode` and `min-links` are the CLI-exposed knobs. Priorities only advertise and break one tie in `selection.rs`: with config-fixed membership and no `max-links`/standby they never change which ports are selected otherwise.

## Modules

| Module | Role |
|--------|------|
| `main.rs` | Single-instance daemon args (`--watchdog-socket`, `--listen-socket`, `--log-socket` — mirrors `interface/src/main.rs`'s shape, not `ospf/src/main.rs`'s per-`--instance` one), resolves `nos-configd` via the broker, starts `server::start`, spawns `reconcile::run` and `interface_client::run` sharing one `mpsc` channel |
| `packet.rs` | Hand-rolled LACPDU encode/decode (at least 110 bytes; versions 1 and 2 accepted with trailing v2 TLVs ignored, other versions dropped and counted), plus Marker PDU decode (`decode_marker`) and Marker Response encode (802.1AX §6.4.2.3 Figure 6-2's 110-byte v1 layout, which we send: Actor/Partner Information TLVs, Collector Information TLV, Terminator TLV) — pure, no I/O, round-trip unit-tested in-file, mirroring `ospf::packet`'s style. No parsing crate: only the fixed v1 offsets are read |
| `socket.rs` | A thin wrapper over the shared `nos-l2-socket` crate (`L2Socket`, also used by `nos-lldp`) fixing its ethertype/group/buffer; `LacpSocket` — a raw `AF_PACKET`/`SOCK_RAW` socket bound to **one physical member interface** (never the bond, never a VRF — same reasoning as `ospf::socket`'s own interface-scoped bind: no demux, so binding wider leaks other links' traffic), restricted to ethertype `0x8809` and joined to the slow-protocols multicast MAC `01:80:C2:00:00:02` via `PACKET_ADD_MEMBERSHIP` (most NIC drivers otherwise never pass an arbitrary multicast destination up to userspace at all). The raw `libc`/`unsafe` (`sockaddr_ll` construction, `PACKET_ADD_MEMBERSHIP`'s `packet_mreq`) now lives in `l2-socket/`, not here. The shared `recv` also drops frames not addressed to the joined group — LACPDUs only ever go to `01:80:C2:00:00:02` |
| `receive_machine.rs` | §6.4.12 Receive Machine — pure `step`, see above |
| `periodic_tx_machine.rs` | §6.4.13 Periodic Transmission Machine timing (`interval_for`) — see above |
| `churn_machine.rs` | §6.4.17 Actor/Partner Churn Detection — pure `step`; `link.rs` runs one per side per port (60s, `NOS_LACP_CHURN_SECS` shortens it for e2e). Beyond the standard's diagnostic-only role, a port with either side `Churn` is left out of the active-member set (no traffic on it); reported as `actor_churn`/`partner_churn` in `show lacp` / `GET /v1/lacp` |
| `mux_machine.rs` | §6.4.15 Mux Machine — pure `step`, see above |
| `selection.rs` | Config-scoped Selection Logic — pure `select`, see above; equal-size partner groups tie-break on the lowest (actor port priority, port number) |
| `link.rs` | Per-port owning struct + `run()` (also answers Marker PDUs, see above) — mirrors `ospf::link.rs`'s per-link shape: owns the socket and all three state machines, drives them off real timer deadlines (`tokio::select!` over the periodic-send ticker, the `Current_While_Timer`, the Mux `Wait_While_Timer`, a `selected` watch-channel, and packet receive), reports every change into the shared observation map |
| `aggregate.rs` | `AggregateManager` — one per configured `Lacp`-mode `PortAggregate`; `reconcile` spawns/stops member `link::run` tasks (restarting *every* member if the resolved Actor System ID changes); an internal `selection_loop` task re-runs `selection::select` on every observation change, feeds each port's own `selected` channel, and pushes the recomputed `Distributing`-state set |
| `interface_client.rs` | Owns the persistent push connection to `nos-interfaced` (`InterfaceRequest::PushLacpMembers`) — full-resend-only (no `Full`/`Add`/`Remove` split like `RibRequest::PushBgpRoutes`; an aggregate has too few members for incremental batching to be worth the complexity), caching every aggregate's last-known state locally so a fresh/reconnected connection can resend everything in one pass |
| `server.rs` | Serves `nos_proto::lacp`'s `LacpRequest::GetSummary` on `--listen-socket` (default `/run/nos/lacp.sock`, registered with the broker as `ServiceRef::Lacp`), reading the shared `reconcile::SharedAggregates` map — each aggregate's `AggregateManager::summary()` (per-port Receive/Mux state, partner identity, `selected`/`synchronized`). Backs `nos-cli`'s `show lacp [<name>]`. Read-only: never touches an aggregate's state |
| (none) | `fetch_config`/`subscribe_diff` and `resolve_with_retry`/`resolve_once` come from `nos-daemon` |
| `reconcile.rs` | Steady-state loop: subscribes to `DiffScope::{Interfaces, PortAggregates}` purely as a resync trigger, always re-fetching the whole config, filters `port_aggregates` for `mode == Lacp`, resolves each one's member set from `Interface.port_aggregate`, drives one `AggregateManager` per name (creating/`shutdown`-ing as aggregates are added/removed from config) — plus a fixed 10s safety-net tick, mirroring `interface::reconcile`'s shape |

- **Tagged frames.** A frame that carried an 802.1Q tag is dropped by a kernel BPF filter (`L2Socket::open_untagged`), even when the NIC/veth offloaded the tag so the bytes read look untagged (#690).

## `nos-e2e lacp`

After the passive/active steps the phase runs `min-links` (`lacp_min_links`): `--min-links 2` with both members `Distributing` changes nothing; router-b withdrawing `eth2` makes router-a log `lacp min-links not met, bond emptied`, release `eth1` from the kernel bond while `GET /v1/lacp` still shows it `Distributing`/`selected`; then `tools/e2e/src/phases/individual.py` (a scripted partner in router-b's netns, 10s of LACPDUs on `eth2` with Actor_State.Aggregation clear) makes router-a report `eth2` `individual=true`, `Current` but not selected; router-b restoring `eth2` refills the bond. **A real Linux bond cannot play the Individual partner**: the kernel bonding driver advertises Aggregation on every slave it was tried with (veth full duplex, dummy/tun unknown or full duplex: port state `0x45`/`0x3d`), and no virtual device here can report half duplex, so the speaker is scripted.

- Inbound LACPDUs are limited to 10/s per port (excess dropped before any machine runs, one `warn!` per burst); `lacp lacpdu received` is logged at `info` only when receive state, mux state or partner changed.
- Active-member pushes to `nos-interfaced` are coalesced to at most one per second (immediate if the last push was >= 1s ago, else the newest set at the window end; a set equal to the last pushed one is not pushed).

Before the withdraw step the phase also injects a real Marker PDU on router-b's eth1 from a python helper container (`tools/e2e/src/phases/marker.py`, raw `AF_PACKET`, source MAC = router-b's own so only router-a answers) and requires a byte-correct Marker Response back plus router-a's `lacp marker answered` log line.

Real two-container verification (see [docs/e2e-phases.md](../docs/e2e-phases.md)): both routers get a real `Lacp`-mode `PortAggregate` over two member links, proving real LACPDU exchange converges both sides' Mux Machines to `Distributing` on both links and that `nos-interfaced` only then enslaves each negotiated member into the real kernel bond. Both routers run `lacp-rate fast`, then the phase withdraws `eth2` from router-b's aggregate by config (router-b stops speaking LACP on it; the link stays up) and confirms router-a's own Receive Machine timeout and the resulting kernel-level release **within 30s** — far under the 90s Long timer, so passing proves the fast rate is really in effect — before tearing the aggregate down.

`show lacp` itself isn't exercised by the e2e phase: `nos-cli` has no scriptable one-shot mode (see root `CLAUDE.md`), so the `LacpRequest::GetSummary` round trip is covered by `lacp/tests/server.rs` (real socket, real `AggregateManager`) and `cli/tests/lacp_client.rs`.

**The member links are direct veth pairs between the two containers' network namespaces, not docker networks** (unlike the static `port-aggregate` phase): a docker network is a Linux bridge, and a Linux bridge never forwards the `01:80:C2:00:00:02` slow-protocols address (the kernel refuses to enable it — it's in the restricted link-local group range), so no LACPDU could ever cross one. A throwaway privileged helper container with iproute2 creates the pairs (`World::link_veths`). The link-loss check withdraws a member by config rather than taking a link down because each `nos-interfaced` re-applies "admin up" on every 10s resync, which would undo a `link set down`.

## v2 codec (#893, UNVERIFIED)

- `Lacpdu.v2: Option<V2Tlvs>`: `None` encodes the unchanged 110-byte v1 PDU; `Some` encodes version 2 with the TLVs after the Collector block (offset 58), then Terminator, padded to 110.
- Assumed TLVs (see [lacp-v2.md](lacp-v2.md)): Port Algorithm 4 (len 6), Conversation ID Digest 5 (len 20, Link_Number + MD5), Masks 6-9 (len 130), Service Mapping Digest 10 (len 18).
- Digest input: 4096 big-endian u16 link numbers, conversation 0 first (assumed). Mask bit order: conversation 0 is the MSB of mask 1 (assumed).
- Decode: unknown types and wrong-length known types are skipped by length; an overrunning length makes `v2 = None`; the v1 fields stay usable; never panics.
- `conversation::send_version(pref, last_partner_version)`: pref 2 sends 2 until a v1 PDU is seen, then 1, back to 2 on a v2 PDU; pref 1 always 1.
