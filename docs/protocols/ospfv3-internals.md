# nos-ospfv3 internals

How `nos-ospfv3` implements OSPFv3 (RFC 5340): functions, data structures, log lines to grep for, `ponytail:` ceilings and the not-done lists. For configuration and behaviour see [OSPFv3](ospfv3.md); the rules to respect when editing the crate are in [`ospfv3/CLAUDE.md`](../../ospfv3/CLAUDE.md). It mirrors [OSPF internals](ospf-internals.md); read that first for everything not called out here. Which `nos-e2e` phase covers what is in [`docs/e2e-phases.md`](../e2e-phases.md).

## Scope (Phase 1)
- Hello / DBD / LSR / LSU / LSAck reaching `Full` over point-to-point and broadcast links (DR/BDR election and neighbor FSM come from `nos-ospf-common`).
- Single-area SPF (RFC 5340 §4.8/§16) with next hops from Link-LSAs (never a live neighbor table), pushed to `nos-ribd` (`rib_push_client`) on every LSDB change (`Lsdb` `Notify`, 50ms hold-down, 2s fallback poll; #190), cut into `PushOspfRoutes` frames like v2's (`--push-chunk`, hidden, test-only, via `--ospfv3d-arg`; #727); the connection is read for EOF, so a restarted `nos-ribd` gets a fresh `Full` at once (#729).
- SPF merges a router's several Router-LSAs/E-Router-LSAs (fragments differ by Link State ID; legacy and extended may coexist) into one body per advertising router: links unioned in `(type, Link State ID)` order with exact duplicates dropped (metric counts), flags OR-ed, options from the lowest Link State ID (E-Router-LSA wins a tie). Originator-side splitting arrives with #853.
- RFC 8362 Full mode (`extended-lsa`, `--ospfv3-extended-lsa`): E-Router/E-Link/E-Intra-Area-Prefix LSAs instead of the legacy set. No Sparse mode. Toggling prematurely ages and floods the other flavor (see the next bullet); MaxAge entries are held `lsdb::MAX_AGE_HOLD_TICKS` (7) ticks so the periodic resend carries them out, skipped by SPF and DBD summaries, and an unheld, unrequested MaxAge LSA received is acked and dropped (RFC 2328 §13 step 4). Self-originated LSAs are held with their wire checksum (`lsa::fill_checksum`) so a neighbor's echo can't undo a flush. Verified by `nos-e2e ospfv3`.
- Withdrawal of LSAs no longer originated (RFC 2328 §13.4/§14.1, #157): every origination tick (`LinkManager::originate_all`) records the keys its passes originated, then `link::withdraw_undesired` prematurely ages every other live LSA of ours of an owned type (legacy or RFC 8362 Router/Network/Link/IAP — never a Grace-LSA) in every area store and every running link's store. Stateless, like `nos-ospfd`'s pass, so one sweep covers a lost DR role or last `Full` neighbor (Network-LSA + its IAP), an emptied router IAP, a left area, a moved Link-LSA key (new `interface_id`), the other RFC 8362 flavor, and a previous incarnation's LSAs learned over DBD. A removed link's store is not swept (no neighbor to flood to). Known ceiling: no RFC 3623 restart mode, so a cold restart that was DR flushes its old Network-LSA (learned back over DBD) until it is DR again — same as `nos-ospfd`. Verified by `nos-e2e ospfv3-flush`.
- Own LSA flooded back newer (RFC 2328 §13.4, #731): same mechanism as OSPFv2 — `handle_lsu` marks it in the store it landed in (`Lsdb::mark_reflected`), wakes `LinkManager::reoriginate`, and `install_self_originated` re-originates at received + 1 even with an unchanged body; marks no pass took are flushed after `originate_all`. No Network-LSA address case: v3's Link State ID is an interface ID.
- RFC 5286 basic loop-free alternates (`spf::alternates`/`pick_backup`, same inequality and `ponytail:` ceiling as `nos-ospfd`: link protection only, one distance-only Dijkstra per neighbor — `run_dijkstra(.., links: None)` skips next-hop derivation, which would otherwise drop vertices from a non-root viewpoint). Differs from v2: the backup is link-local too, so it carries its own `backup_interface_id` (`OspfRoute`/`RibEntry`) and can leave over a different link than the primary; and `nos-ribd` installs an IPv6 backup at 2000, not 1000 (an IPv6 primary is 1024). Verified by `nos-e2e ospfv3-lfa`.
- RFC 7166 authentication trailer (`Ospfv3Profile.auth`) — see "Authentication" below. Verified by `nos-e2e ospfv3-auth`.
- RFC 4222 Hello prioritisation and any-packet neighbor liveness (`biased;` select, `last_heard`/`note_alive`) — same as `nos-ospfd`, see [OSPF internals](ospf-internals.md)'s "Hello prioritisation and liveness".
- RFC 5187 graceful restart — see "Graceful restart" below. Verified by `nos-e2e ospfv3-graceful-restart`.
- RFC 5340 §A.3.1 Instance ID (header byte 14, after the kernel-filled checksum at 12 — stamping 12 corrupts the checksum): `Ospfv3Profile.instance_id` (0-31, `None` = 0) → `LinkConfig.instance_id`. `encode_*` write 0; the socket (`OspfSocket::signed`, and the in-memory wire) stamps the link's value with `packet::set_instance_id` before signing (the RFC 7166 digest covers the header). `link::run` drops a mismatch (`debug!`, `"ospfv3 packet instance id mismatch, dropping"`) **before** `verify_trailer`, so another instance's packets never count as auth failures. Verified by `nos-e2e ospfv3-instance-id`.
- ABR and ASBR (#50) — see "ABR, ASBR and the AS-scope LSDB" below. Verified by `nos-e2e ospfv3-asbr`/`ospfv3-abr`.
- Unknown LSA types (RFC 5340 §2.9/§A.4.2.1, #47): `decode_body` returns `LsaBody::Opaque(raw)` (re-encoded verbatim, checksum intact) instead of failing the packet. `lsa::is_link_local_scope`/`is_as_scope` use the *effective* scope — S2/S1 for a known type or U=1, link-local for unknown U=0 — so `exchange::on_lsu_received` stores it and flooding follows with no other change; S2/S1 `11` (`is_reserved_scope`) is discarded unacked (§4.5 step 3). SPF ignores it. RFC 5340 §3.4 deprecated the stub-area restriction, so nothing filters on area type. Unit-tested only (owner decision: no e2e — there is no way to put an unknown LSA on the wire without a test-only flag or a scripted speaker).
- Prefix options (RFC 5340 §A.4.1.1, #49): `lsa::PREFIX_OPT_{NU,LA,P,DN}` (`0x01/0x02/0x08/0x10`). A received NU prefix is skipped by `spf::compute` and `intra_area_routes` (so never summarized either); a loopback `/128` is originated with LA (`link::originate_intra_area_prefix_lsas`), every other prefix with `0`; a received LA prefix is routed as-is. P/DN are never set (no NSSA translation, no PE-CE). Unit-tested only: the REST database view doesn't expose prefix options, and `nos-e2e ospfv3` proves LA-flagged loopbacks still route.
- **Not yet** (OSPFv2-only for now): stub areas/NSSA, area ranges, virtual links; RFC 5838 multi-AF (AF-bit, several instances on one link).

## ABR, ASBR and the AS-scope LSDB

A port of [OSPF internals](ospf-internals.md)'s "ASBR" and "ABR" sections; only the differences are listed.

- **LSAs** (`lsa.rs`): Inter-Area-Prefix `0x2003`, Inter-Area-Router `0x2004`, AS-External `0x4005` (§A.4.5-§A.4.7, `LsaBody::InterAreaPrefix`/`InterAreaRouter`/`AsExternal`) and their RFC 8362 forms `0xA023`/`0xA024`/`0xC025` (one TLV each, no fixed part; the external's forwarding address and tag are sub-TLVs, and it has no referenced LSA). Decoded faithfully; originated Type-1, metric `spf::EXTERNAL_METRIC` (20), no forwarding address/tag/referenced LSA. `LsaTypes` picks the flavor, and `OWNED_TYPES` lists all fourteen, so `withdraw_undesired` flushes either.
- **AS-scope store** (`LinkManager.as_lsdb`, `lsa::is_as_scope`): one store for the router, not one copy per area as in v2. `exchange::on_lsu_received` routes S2/S1 = `10` there; every link's DBD summary, LSR answer and flood read it (`link::Stores`), `age_lsdbs` ages it, `database_summaries` lists it under area `0.0.0.0` with `link: None`, and `compute_routes` adds it to every area's SPF input. So an ASBR's LSA learned in one area reaches the others with no ABR code.
- **ASBR**: `nos-ribd`'s `ospf_client` (one task per family, `Peer` `OSPFV2`/`OSPFV3`) pushes the table's IPv6 statics when `redistribute … to ospfv3` (`Ospfv3Request::RedistributeRoutes`, `ribd` only — `server::allowed`). `apply_redistribute_update`/`set_redistribute_policy` re-filter at once (v2 waits for the 10s resync). A chunked `Full` is staged by `server.rs` and applied once, like v2's (#728). `reconcile::resolve_redistribute_policy` is a copy of v2's (`ponytail:`). E-bit on the Router-LSA while the filtered set is non-empty.
- **ABR** = links or loopbacks in 2+ areas (`attached_areas`); B-bit on the Router-LSA. `originate_inter_area_lsas` summarizes `spf::intra_area_routes` (distance-only Dijkstra over Intra-Area-Prefix-LSAs, root's own included — v2 skips transit networks — plus E-bit routers) into every other attached area. Never re-summarizes an inter-area or external route.
- **Link State IDs** of prefix-keyed LSAs are opaque in v3: `LinkManager::lsid` hands one out per `(type, prefix)` from a never-reused counter, pruned once a prefix is no longer originated; a restart or re-advertise gets a new ID and `withdraw_undesired` flushes the old ones. An Inter-Area-Router-LSA's ID is the ASBR's router ID.
- **SPF** (`spf.rs`): inter-area via the ABR's distance + LSA metric; external via an intra-area E-bit Router-LSA or the cheapest Inter-Area-Router-LSA, + the **LSA's own metric** (v2 adds a constant). Own LSAs never route. `ponytail:` metric-only precedence (no §16.4 classes), Type-2 treated as Type-1, forwarding address ignored, an ABR uses every area's summaries (no §16.2 backbone-only rule).
- **Transit-link gate** (RFC 5340 §4.4.3.2/§4.4.3.9, #958): a broadcast link is in the Router-LSA only once `link::adjacent_to_dr` (DR neighbor `Full`, or we are the DR with a `Full` neighbor; mirror of v2's). Until the network-referenced Intra-Area-Prefix-LSA exists (`link::network_prefix_originated`: DR with a `Full` neighbor), the link's prefix rides the router-referenced one; the two sets are exact complements at rest (a swap may show both for up to `MinLSInterval`). SPF treats a router-referenced prefix as a stub off that router.
- **Options**: `link::OWN_OPTIONS` sets E in every Hello/DBD and self-originated LSA (every area is normal, §A.2); a received E-bit is not checked (no stub areas yet).

## Authentication (RFC 7166)

`Ospfv3Profile.auth: Option<Vec<OspfCryptoKey>>` — the same `nos_proto::OspfCryptoKey` as `OspfProfile`'s `OspfAuth::Crypto`, with no enum wrapper since RFC 7166 has exactly one mechanism (HMAC-SHA-1/256/384/512; `Md5` is rejected at commit, §4.3 defines none) and no simple password. Same CLI/ops/REST as `ospf profile` (`set … crypto-key <key-id> <algorithm> <label>`, `crypto-key <key-id> current`, `delete crypto-key <key-id>`, `delete auth`; `Ospfv3ProfileOp::{SetCryptoKey,RemoveCryptoKey,SetCryptoCurrentKey,ClearAuth}`; provision `--ospfv3-crypto-key <key-id>:<algorithm>:<secret>`, which stores the secret under admin label `ospfv3-<profile>-key<id>`; `nos-ospfv3d` resolves labels like `nos-ospfd`, #509). `key_id` is the 16-bit Security Association ID — which is why `OspfCryptoKey.key_id` is `u16` for both protocols (see [OSPF internals](ospf-internals.md)).

Wire mechanics, all in `packet.rs` (`TrailerAuth::sign`/`verify_trailer`, pinned by a test recomputing the HMAC independently):
- **AT-bit** `lsa::OPTION_AT` (`0x000400`, §2.1/§7) set in Hello/DBD Options by `link::link_options` when the link has keys; LSR/LSU/LSAck carry no Options and inherit the link's setting. A received Hello/DBD whose AT-bit disagrees with the link's config, or an authenticated link receiving a packet with no trailer, is `AuthTypeMismatch`.
- **Trailer** (§4.1, after the packet, outside its `Length`): Auth Type `1`, Auth Data Len (`16 + L`), Reserved, SA ID (= `key_id`), 64-bit sequence, then the digest. `decode_header` now bounds every body by `Length`, so trailing bytes never reach a body decoder.
- **Digest** (§4.4/§4.5): `Ks = key || 0x0001` (OSPFv3's Cryptographic Protocol ID — the one step with no `ospf::packet` precedent), `Ko = H(Ks)` if longer than `L` else zero-padded to `L`, then `HMAC(Ko, packet || trailer header || Apad)` with `Apad` = the 16-byte IPv6 source address followed by `0x878FE1F3` (`ospf::packet::apad`'s RFC 7474 shape with a 16-byte source). Compared in constant time (`hmac::Mac::verify_slice`).
- **Checksum** (§2.2/§4.2): an authenticated `OspfSocket` does **not** set `IPV6_CHECKSUM` — the field stays `0` and the kernel neither fills nor verifies it; the digest covers the packet instead.
- **Where it runs**: the socket signs every send (`socket::OspfSocket::open(.., auth)`, owning the sequence counter — wall-clock-seconds floor, `ospf::link`'s classic `AuType` 2 scheme, not RFC 7474's persisted boot count); `link::run` verifies every receive before `packet::decode` and keeps `NeighborInfo.last_crypto_seq` per neighbor and per packet type (RFC 7166 §4.6; `accept_crypto_sequence`, a non-increasing number is dropped and logged `"ospfv3 packet crypto sequence number not increasing, dropping"`). Failures log `"ospfv3 packet authentication failed"` with `link`/`source`, and a key change restarts the link like any other `LinkConfig` field.
- No LLS (RFC 5613) in either OSPF version, so the L-bit/LLS part of the digest scope never applies.

## Graceful restart (RFC 5187)

- **Grace-LSA** is a native type (`lsa::LSA_TYPE_GRACE` `0x000B`, link-local, `LsaBody::Grace`): RFC 3623's Grace Period and Restart Reason TLVs, no IP-address TLV (OSPFv3 identifies neighbors by router ID). SPF ignores it.
- **Restarting side**: `Ospfv3Instance.graceful_restart_grace_period` (`LinkManager::set_graceful_restart`). Only SIGTERM (`main::wait_for_shutdown_signal`) announces it — the watchdog's SIGINT means stop/removal, with no restart to wait for. `main` calls `LinkManager::announce_graceful_restart` before signalling shutdown (the log forwarder stops on that signal), which asks every link task (`LinkEntry.grace_tx`) to unicast one Grace-LSA to each `Full` neighbor, twice, 500ms apart (`GRACE_SEND_WINDOW`), then exits. Nothing is prematurely aged on shutdown (the sweep runs on origination ticks only, see Scope); the restarted process resyncs cold.
- **Helper side**, always on: `handle_lsu` acts on a newly installed Grace-LSA from a `Full` neighbor (`on_grace_lsa` sets `NeighborInfo.grace_deadline`) and removes it from the link store at once — held, it would be offered back to the restarted router and flooded to us again. While in grace: `sweep_dead_neighbors` skips (and never removes) the neighbor, a Hello that doesn't list us keeps its state, and `Lsdb::age_and_evict` holds its LSAs below `MaxAge`. The restarted neighbor's Init DBD while we still hold it `Full` resynchronizes it through the general RFC 2328 §10.6 rule (see [OSPF internals](ospf-internals.md)'s "DBDs in `Loading`/`Full`", shared by both daemons). Grace ends on reaching `Full` again, on a `MaxAge` Grace-LSA, at the deadline (`expire_grace`, 1s tick), or on a topology change. The deadline is `helper_deadline_secs` (Grace-LSA period minus its age, capped by `LinkConfig.helper_max_grace_period`; none left logs `no grace left, exiting grace`); the `grace period entered` line carries `effective_grace`.
- **Strict LSA checking** (RFC 3623 §3.2 item 3, which v3 inherits; RFC 5187 only defines the Grace-LSA): `Lsdb::install` records the origin of every new, changed or flushed LSA for which `Lsa::is_topology` holds (function codes 1-5, 9 and the RFC 8362 forms `0x21`-`0x25`, `0x29`, area or AS scope; Link-LSAs are link-local and excluded, since they never leave the link), local originations included, refreshes excluded. `LinkManager::age_lsdbs` drains each area store and `as_lsdb` and sends the origins to the links over `LinkEntry.topology_tx` (area-store changes only to that area's links, AS ones to all); `exit_grace_on_topology_change` ends the grace of every helped neighbor other than an origin (`ospfv3 helper: topology change, exiting grace`) and restarts its inactivity clock.
- Routes need nothing: `nos-ribd` keeps OSPF routes of a disconnected push client, and the helper's SPF still sees the held LSAs.

## Link state from `nos-interfaced` (#276)

- A copy of `nos-ospfd`'s ([OSPF internals](ospf-internals.md), "Link state from `nos-interfaced`"): `link_client` (stream, `LinkTable`, `apply`, `gate`), the gate and the keep-running-link rule in `reconcile::resync`, the debounced watch arm in `run()` (200ms, resync only when a watched device's gate changed; the 10s tick stays).
- **Gate**: `Down(absent | admin-down | no-carrier)` leaves the link out of `desired_links`, so `LinkManager::reconcile` aborts it (`ospfv3 link stopped`). `Ungated` falls back to `if_nametoindex`. Logs on transitions only.
- **Interface ID**: `LinkConfig.interface_id` is the stream's ifindex, so a device recreated with another ifindex restarts the link; `reconcile::pick_interface_id` falls back to `if_nametoindex`, then to the running link's.
- **Keep the running link**: a failed VRF, address or bridge lookup falls back to the running value (`merge_running`, `LinkManager::running_config`, log once per link). An attach point whose config has no IPv6 address (`has_address`) or no routing table gets no fallback. `ponytail:` an address removed by hand while the config still carries it is noticed on the next config change, not by the 10s tick.
- Tests: `link_client::tests`, `reconcile::tests::{merge_running_table,interface_id_prefers_stream_then_running,gate_link_logs_state_and_skips_down,signature_only_covers_watched_devices}`, `link::tests::{running_config_follows_the_task,interface_id_change_restarts}`; `nos-e2e ospfv3`.

## Layout
`socket` (raw socket) · `packet` (wire codec) · `lsa` (LSAs) · `lsdb` (alias of `nos_ospf_common::lsdb::Lsdb<Lsa>`: per-area database, aging, `MAX_AGE_HOLD_TICKS`, `MIN_LS_ARRIVAL`) · `exchange` (v3's closures and three stores over `nos_ospf_common::exchange`, which runs the DBD/LSR/LSU/LSAck machine for both daemons: S2/S1 store routing, reserved-scope discard, the Grace-LSA `MaxAge` exemption) · `link` (per-link driver task + `LinkManager`) · `reconcile` (config → `LinkConfig`, redistribute policy) · `server` (IPC queries + `nos-ribd`'s redistribution feed) · `rib_push_client`.

**LSDB scope** (RFC 5340 §4.5.1, #46): `LinkManager` holds one `Lsdb` per *area* (`lsdbs`, Router/Network/Intra-Area-Prefix and their E- forms) and one per *link* (`link_local_lsdbs`, keyed by attach point: Link-LSA/E-Link-LSA only, `lsa::is_link_local_scope`). A link's DBD summary, LSR answer and periodic flood read its area store plus its *own* link store, so a Link-LSA is never offered on a link other than the one it was received/originated on — `nos-ospfd` doesn't need this since OSPFv2 has no link-local scope. SPF (`compute_routes`) and `show ospfv3 database` (`Ospfv3LsaSummary.link = Some(attach_point)`) merge every same-area link store back in. `Lsdb` itself is scope-oblivious and shared with `nos-ospfd` (`nos-ospf-common`); like v2, `on_lsu_received` uses `install_received`, so a newer instance arriving within `MinLSArrival` (1s) of the previous received one is dropped unacked until the sender's 5s retransmission; `exchange::on_lsu_received` routes each received LSA by its S2/S1 bits.

**Delayed acks** (RFC 2328 §13.5, as `nos-ospfd`): `on_lsu_received` queues every ack in `AdjacencyData.pending_acks`; `link::flush_pending_acks`, on the 5s `RXMT_INTERVAL` sweep, sends each neighbor's batch as one `LSAck` (on a broadcast link, one deduplicated set to the group) and logs `ospfv3 lsack sent acked=.. delayed_ms=..`. `ponytail:` every ack is delayed (no direct-ack case, as v2). Verified by `nos-e2e ospfv3-asbr`.

## Things that differ from `ospf/`
- **Checksum**: the IPv6 upper-layer checksum is done by the kernel via `IPV6_CHECKSUM` (offset 12), set in `socket::open` — `packet.rs` doesn't compute it. Skipped on an authenticated link (RFC 7166 §2.2/§4.2, see "Authentication").
- **No IP header strip**: Linux IPv6 raw sockets deliver only the payload.
- **Hop limit 1**: unicast and multicast hops are both set to 1 on the socket (link-local scope; there are no virtual links). `ospf/src/socket.rs` does the same for IPv4 TTL.
- **Multicast groups** (#854): `ff02::5` (AllSPFRouters) is joined at socket open. `ff02::6` (AllDRouters) is joined only while the broadcast link's election result is DR or Backup, and left on demotion; never on point-to-point. `link::run_election` drives it through `nos_ospf_common::drouters` and logs `ospfv3 all-drouters membership changed ... joined=<bool>` on change only. A failed join/leave is a `warn!` and retried on the next election pass. On broadcast links the periodic LSU flood and the delayed LSAck are multicast (#879, RFC 5340 §4.5 = RFC 2328 §13.3/§13.5): `ff02::5` as DR or Backup, `ff02::6` otherwise (`OspfSocket::send_all_drouters`, `LinkSocket::send_flood`; one signed packet per chunk is valid for every receiver, RFC 7166 trailers included). A failed group send warns and that pass falls back to unicast. DBD/LSR, retransmitted LSUs, Grace-LSAs and point-to-point links stay unicast. Logged as `ospfv3 lsu flood destination changed link=.. dest=..`, only on change.
- **Router-LSA split** (#853): a router's links are cut into several Router/E-Router-LSAs (`link::split_router_links`), each within `min(link MTU in the area) - (40 + 16 + 4 + 20 header + 4 flags/options + largest RFC 7166 trailer)`; a link is never split. Fragment 0 keeps the router id as Link State ID, then `0.0.0.1`, `0.0.0.2`, ...; flags and options are identical. Surplus fragments are aged by `withdraw_undesired` when the link set shrinks; the Intra-Area-Prefix-LSA still references fragment 0. The receive side unions all fragments (#852). `--router-lsa-max-links` caps links per fragment, test-only via `--ospfv3d-arg`; logs `ospfv3 router-lsa split area=<a> fragments=<n>`; verified by `nos-e2e ospfv3-router-lsa-split`.
- **DBD pagination** (RFC 2328 §10.8): the per-packet header budget is `exchange::mtu_based_max_headers(LinkConfig.mtu)` — MTU minus IPv6 (40) + OSPFv3 header (16) + DBD body (12), over the 20-byte LSA header. `Ospfv3Profile.mtu` overrides the interface MTU (`reconcile::resolve_effective_mtu`); `--dbd-max-headers` is a test/debug override only. LSU, LSR and LSAck are cut the same way (`link::split_budget`: MTU minus IPv6 40, OSPFv3 header 16, LSU count 4 and the RFC 7166 trailer when authenticated; an LSA over the budget goes alone), one packet per chunk with its own trailer sequence; an LSU needing several packets logs `ospfv3 lsu split link=<l> packets=<n>`. Verified by `nos-e2e ospfv3-mtu-pagination`. The RFC 5340 A.3.3 Interface MTU check (`exchange::mtu_acceptable`, `link::handle_dbd`, `ospfv3 dbd rejected`) and `Ospfv3Profile.mtu_ignore` work as in `nos-ospfd`; verified by `nos-e2e ospfv3-mtu-mismatch`.
- **Receive hardening** (#394): a packet whose source is not link-local is dropped with a `debug!` before any other check (RFC 5340 §4.2.2, every packet type); `handle_hello` caps a link at `MAX_NEIGHBORS_PER_LINK` (64) neighbors and rate-limits its mismatch warnings. Details in `ospf-internals.md`.
- **Neighbor table hygiene** (#957, mirrors #956 in [OSPF internals](ospf-internals.md)):
  - The 1s `sweep_dead_neighbors` is the only dead timer, on every network type (no single p2p deadline); it logs `ospfv3 neighbor state changed to down link=… neighbor=…`.
  - A `Down` entry without `grace_deadline` idle for `dead_interval` is removed on a later tick (`ospfv3 neighbor entry removed link=… neighbor=…`), so forged router IDs no longer pin the 64-entry cap.
  - On point-to-point and point-to-multipoint (never broadcast) a Hello from a link-local address held by another live, non-grace entry puts that entry `Down` (adjacency cleared) before the cap check: `ospfv3 neighbor evicted, same address new router id`. Unlike #956 this covers p2mp too.
  - `router_lsa_links` names the lowest router ID among `Full`/grace entries, independent of map order.
  - Verified by `nos-e2e ospfv3-p2p-rid-change`; forged-Hello floods are unit-test only.
- Timers (`--lsa-age-multiplier`) are test-only, like in `nos-ospfd`.
