# IPC protocols (`nos-proto`)

Inventory of the wire types in `nos-proto`: one row per module, with the request/event enums, who serves it and what the non-obvious semantics are. The framing is `IpcCodec` (4-byte little-endian length + postcard payload); variants are only ever appended (see [`proto/CLAUDE.md`](../proto/CLAUDE.md)). The security model (roles, allow-lists) is in [IPC security](architecture/ipc-security.md) and the endpoint directory in [Endpoint broker](architecture/endpoint-broker.md). Config-tree types are in [Schema reference](schema-reference.md).

| Module | Request/event types, served by, semantics |
|---|---|
| `ipc` | IPC message types: `Request` (client→server) and `Event` (server→client), plus `TransactionBase` and `TransactionSnapshot`. `Request::SubscribeDiff { scopes: Vec<DiffScope> }` streams `Event::Diff(ConfigDiff)` scoped to `scopes` — an initial diff against an empty config, then one per commit touching a requested scope — as an alternative to `Request::Subscribe`'s full-snapshot `Event::Config` stream. `Request::EditTransactionPath` (#774) sets or removes one config-path subsection of a transaction and replies `Event::TransactionEdit { generation, dirty, value }` (`value`: JSON text of the edited subsection, unredacted, `None` after a remove); the older `SetTransactionPath` (full `Event::Transaction` reply) is kept for the wire indexes only. |
| `broker` | `ServiceRef` (`Config` / `RibTable(String)` / `Interfaces` / `Log` / `BgpInstance(String)` / … / `Lacp`), `WatchdogRequest::ResolveEndpoint { service }`, `WatchdogEvent::Endpoint(PathBuf)` / `NotAvailable` — `nos-watchdogd`'s endpoint-resolution protocol, so no client needs to hardcode another daemon's socket path. `Interfaces`/`Log`/`Lacp`/`Lldp` (unlike `RibTable`/`BgpInstance`) carry no name — there's exactly one `nos-interfaced`, one `nos-logd`, one `nos-lacpd`, and one `nos-lldpd` instance, each resolved directly like `Config` rather than through the registry. |
| `Role` (in `broker`) | `Role` (`Watchdog`/`Configd`/`Logd`/`Bgpd`/`Ribd`/`Ospfd`/`Ospfv3d`/`Interfaced`/`Lacpd`/`Lldpd`/`Fdbd`/`Restd`/`Bfdd`/`Stpd`/`User`) is what a certificate's `nos://<role>/<name>` URI SAN asserts — never on the wire — with `ServiceRef::role()`/`instance()` giving the identity a client must see before it sends anything. `WatchdogRequest::Login { user, password, csr_der }`/`RenewCert { csr_der }` and `WatchdogEvent::Issued { cert_der, lifetime_secs }`/`Denied` are the login exchange (a manual `Debug` hides the password, like `UserOp`); see docs/architecture/ipc-security. |
| `rib` | `RibRequest::GetRoutesPage { after: Option<IpNet>, limit }` (keyset-paged table, #713; the old `GetRoutes`/`RibEvent::Routes` slots stay for the wire indexes and `GetRoutes` is answered with `RibEvent::Error`) / `Lookup { addr }` / `GetVrfName` / `GetTableId` / `PushBgpRoutes(BgpRouteUpdate)` / `PushEvpnRoutes(EvpnUpdate)` (received Type-5 and symmetric IRB MAC+IP routes, from the underlay `nos-bgpd`; `RouteSourceKind::Evpn`, `RouteEntry.evpn: Option<EvpnRouteInfo>`), `GetEvpnIrb` → `RibEvent::EvpnIrb(Option<EvpnIrb>)` (`fdbd` only: the IP-VRF's L3 VNI, Router's MAC and export RTs, for RFC 9135 symmetric IRB), `PushVpnRoutes(Vec<VpnRouteUpdate>)` (`bgpd` only, the VPN routes the underlay instance imports into this VRF: `VpnRoute { prefix, paths: Vec<VpnPath { pe_next_hop, rd, gateway, interface_id, labels }> }`, never empty, `RouteSourceKind::Vpn`, `RouteEntry.mpls_labels`/`vpn` one entry per gateway; `VpnRouteUpdate` is `Full`/`Add`/`Remove` plus `FullPart` for a `Full` cut across frames by `VpnRouteUpdate::frames`, weight paths + 1 per route), `PushOspfRoutes(Vec<OspfRouteUpdate>)` (`ospfd`/`ospfv3d` only, fire-and-forget SPF results as `OspfRoute`s; `OspfRouteUpdate` is `Full`/`Add`/`Remove` plus `FullPart` for a `Full` cut across frames by `OspfRouteUpdate::frames`, weight next hops + 1 per route, at most `ospf_push_chunk()` per frame: `OSPF_PUSH_CHUNK` = 65536, or env `NOS_OSPF_PUSH_CHUNK` for tests), `ResolveNextHop { addrs }` → `RibEvent::NextHops(Vec<Option<ResolvedNextHop { gateway, interface_id, source }>>)` (`bgpd`/`user`/`restd`: longest match over non-BGP candidates), `GetVpnLabel` → `RibEvent::VpnLabel(Option<u32>)` (`user`/`restd`: the VRF's label), `RibEvent::RoutesPage { routes: Vec<PrefixRoutes>, next: Option<IpNet> }` (`next` = last prefix, the next `after`; `None` on the last page) / `Match(PrefixRoutes)` / `NoMatch` / `Error` / `VrfName(Option<String>)` / `TableId(Option<u32>)`, plus `PrefixRoutes` (a prefix + its candidates, best-to-worst), the wire twins `RouteEntry`/`RouteSourceKind` of `nos-rib`'s internal `RibEntry`/`RouteSource`, and `BgpRoute`/`BgpRouteUpdate` (`Full`/`Add`/`Remove`, plus `FullPart` for a `Full` cut across frames by `BgpRouteUpdate::frames`, mirroring `bgp`'s `RedistributedRoute`/`RedistributeUpdate` for the opposite direction) — `nos-ribd`'s route-query-and-push protocol. `GetVrfName`/`VrfName` is the first direct daemon-to-daemon link in the system: `nos-interfaced`'s Linux driver queries the owning `nos-ribd` instance (found via the broker's `ServiceRef::RibTable`) for its Linux VRF interface name, since that name is allocated and owned entirely by `nos-ribd`'s driver and can't be derived independently. `GetTableId`/`TableId` is symmetric — the same driver also needs the table's raw numeric kernel table id (not just its VRF name) to name the kernel device for a loopback interface (`lo<table_id>`, see `schema::interface::LOOPBACK_PREFIX`). `PushBgpRoutes` is fire-and-forget (no reply), sent by the owning `nos-bgpd` instance's `bgp::rib_push_client` over a persistent connection — the second direct daemon-to-daemon link, and the reverse direction of `bgp`'s `RedistributeRoutes` below. |
| `interface` | `InterfaceRequest::GetInterfaces` / `GetInterface { name }` / `GetPortAggregates` / `GetPortAggregate { name }`, `InterfaceRequest::PushLacpMembers(LacpAggregateMembers)` (fire-and-forget, always the whole active-member set of one aggregate — `nos-lacpd`'s negotiated `Distributing` ports, the only thing gating a `Lacp`-mode member's kernel enslavement), `InterfaceRequest::PushBfdMembers(BfdAggregateMembers)` (fire-and-forget, the whole micro-BFD Up set of one aggregate with `bfd` — `nos-bfdd`'s alone; a member is enslaved only while in it, besides the LACP rule), `InterfaceRequest::SubscribeLinks` (streaming: `InterfaceEvent::LinkSnapshot { observed, links }` first and after any lag, then `LinkChanged(LinkState)` / `LinkRemoved { name }`; `LinkState { name, ifindex, admin_up, carrier, port_aggregate }` is the kernel's observed link state, `port_aggregate` naming the `PortAggregate` whose bond the device is; `ospfd`/`ospfv3d`/`stpd`/`acld` only), `InterfaceRequest::SetStpPortStates(Vec<StpPortAssignment { port, domain, state: StpPortState }>)` / `FlushFdb { port, domain }` (fire-and-forget, `nos-stpd`'s alone: the kernel bridge-port state of a `(port, domain)` — `Blocking`/`Learning`/`Forwarding` — and a flush of its learned MACs; honoured only while `spanning-tree mode` is not `disabled`), `InterfaceRequest::SetErrDisabled { port, disabled }` (fire-and-forget, `nos-stpd`'s alone: BPDU guard shut `port`, so its link is administratively down and no resync brings it up until `disabled: false`), `InterfaceEvent::Interfaces(Vec<InterfaceStatus>)` / `Interface(InterfaceStatus)` / `PortAggregates(Vec<PortAggregateStatus>)` / `PortAggregate(PortAggregateStatus)` / `NotFound`, plus `InterfaceStatus` (the wire twin of `nos-interface`'s internal `InterfaceState`, carrying a nested `Vec<SubinterfaceStatus>` — the wire twin of `SubinterfaceState`, `Subinterface`'s per-tag status) and `PortAggregateStatus` (the wire twin of `PortAggregateState`, mirroring `InterfaceStatus` minus the loopback-only flat fields) — `nos-interfaced`'s interface/port-aggregate-query protocol. |
| `bgp` | `BgpRequest::GetSummary`/`GetEvpnRoutesPage { after: Option<EvpnRouteCursor>, limit }` (`BgpEvent::EvpnRoutesPage { routes, next }`, backing `show bgp evpn`)/`GetFlowspecRoutesPage { after: Option<FlowspecRouteCursor>, limit }` (`BgpEvent::FlowspecRoutesPage { routes: Vec<FlowspecRouteSummary>, next }`, backing `show bgp flowspec`; `dataplane` on the selected copy; #723)/`GetRpkiSummary`/`ShowBmp { instance }` (`BgpEvent::BmpStatus(Vec<BmpStationStatus>)`, backing `show bgp bmp`)/`GetRoutesPage { after: Option<BgpRouteCursor>, limit }` (`BgpEvent::RoutesPage { routes: Vec<BgpRouteSummary>, next }`, keyset-paged, backing `show bgp routes`; `BgpRouteCursor { prefix, peer: Option<IpAddr>, path_id }` is the sort key, its text form is opaque URL-safe base64 of its postcard bytes, `nos_proto::page`; the old `GetRoutes`/`BgpEvent::Routes` slots stay for the wire indexes and `GetRoutes` is answered with the appended `BgpEvent::Error`)/`GetVpnRoutesPage { family, rd, after: Option<VpnRouteCursor>, limit }` (`BgpEvent::VpnRoutesPage { routes: Vec<VpnRouteSummary>, next }`, backing `show bgp vpnv4|vpnv6`; the cursors are each query's sort key, `EvpnRouteCursor { peer, route }`, `FlowspecRouteCursor { peer, family, nlri }`, `VpnRouteCursor { peer, rd, prefix }`, with the same opaque text form; the old `GetEvpnRoutes`/`GetFlowspecRoutes`/`GetVpnRoutes` and their reply slots stay for the wire indexes and are answered with `BgpEvent::Error`)/`RedistributeRoutes(RedistributeUpdate)` (`ribd` only, fire-and-forget, also `OspfRequest`/`Ospfv3Request::RedistributeRoutes`: `RedistributedRoute { prefix, gateway }`, `Full`/`Add`/`Remove` plus `FullPart` for a `Full` cut by `RedistributeUpdate::split()` at `redistribute_chunk()` routes, `REDISTRIBUTE_CHUNK` = 65536 or env `NOS_REDISTRIBUTE_CHUNK` for tests; `nos-bgpd`/`nos-ospfd`/`nos-ospfv3d` stage the parts per connection and apply once on the closing `Full`, `RedistributeUpdate::absorb`)/`RedistributeVpnPrefixes { table, update: VpnPrefixUpdate }` (`ribd` only, fire-and-forget: a VRF's exported routes, `VpnPrefix { rd, prefix, labels, ext_communities }`, `Full`/`Add`/`Remove(rd, prefix)` plus `FullPart` for a `Full` cut by `VpnPrefixUpdate::split_with` at `evpn_push_budget()` encoded bytes; `nos-bgpd` stages the parts per connection and table, `VpnPrefixUpdate::absorb`), `BgpEvent::Summary(Vec<PeerSummary>)`/`RpkiSummary(Vec<RpkiCacheStatus>)` (one entry per configured `BgpInstance.rpki_caches` cache, backing `show bgp rpki`) (received EVPN routes, NLRI pre-rendered by `nos-bgpd`, backing `show bgp evpn`), plus `PeerSummary` (peer address, peer-group, remote AS/BGP ID once negotiated, `BgpSessionState`, uptime, negotiated hold-time/keepalive) — one `nos-bgpd` instance's session-summary protocol, backing `nos-cli`'s `show bgp brief`. `BgpSessionState::Idle` is a reporting-only value (`nos-bgp::fsm` itself only models `OpenSent`/`OpenConfirm`/`Established`) meaning no connection attempt has an OPEN in flight yet. |
| `log` | `LogRequest::Push(LogEntry)` / `GetLogs { source, limit }` / `Tail { source }`, `LogEvent::Logs(Vec<LogEntry>)` / `Line(LogEntry)` / `Error`, plus `LogEntry` (timestamp, level, source, target, message, fields) and `LogLevel` — `nos-logd`'s log-collection protocol. `Push` is the one request every other component process sends continuously over one long-lived connection rather than one-shot, and gets no reply; `GetLogs`/`Tail` are `nos-cli`'s one-shot snapshot and live-tail queries respectively, with `Tail` replying once with the current buffer before streaming further `Line`s. |
| `ospf` | `OspfRequest::GetNeighbors`/`GetDatabase`, `OspfEvent::Neighbors(Vec<NeighborSummary>)`/`Database(Vec<LsaSummary>)`, plus `NeighborSummary` (link display name, area id, neighbor router-id once a Hello arrives, `OspfNeighborState`, seconds since the last Hello, configured hello/dead interval) and `LsaSummary` (one installed LSA's header fields plus a few body facts tests and operators need — an external's metric/E bit, a Router-LSA's flags and virtual-link endpoints — never the full body) — one `nos-ospfd` instance's neighbor-summary and LSDB-summary protocols, backing `nos-cli`'s `show ospf neigh`/`show ospf database`. Mirrors `bgp`'s shape: `OspfNeighborState` models the full RFC 2328 §10.5 ladder (`Down` through `Full`), backed by a real per-area LSDB — see OSPF internals. |
| `lacp` | `LacpRequest::GetSummary`, `LacpEvent::Summary(Vec<PortAggregateLacpSummary>)`, plus `PortAggregateLacpSummary` (aggregate, actor system id/key, configured `LacpRate`, per-port `LacpPortStatus` incl. its `LacpMode` and, as its last field, `unsupported_version_pdus: u64` (#688; postcard is positional, so adding it changed the `GetSummary` wire format: daemons and CLI ship in one image, no shim)) and the `LacpReceiveState`/`LacpMuxState` wire enums — one `nos-lacpd`'s state-query protocol, backing `nos-cli`'s `show lacp`. Only one instance exists, so unlike `bgp`/`ospf` there's no per-instance socket to pick between. |
| `fdb` | `FdbRequest::GetMacs` / `PushEvpnRoutes(EvpnUpdate)`, `FdbEvent::Table(FdbTable)` (its `neigh_suppress` is the ARP/ND suppression nos-fdbd last applied to the VXLAN port), plus the EVPN wire shape shared with `bgp` (`EvpnKey`, whose `EthernetSegment` is a Type-4, `IpPrefix { rd, prefix }` a Type-5 (its L3 VNI in `EvpnRoute::vni`) and `EthernetAd { rd, esi, tag, origin }` a Type-1 (`AD_TAG_ES` = per-ES; `origin` is not on the wire), `EvpnRoute` with its Type-2 `esi` and `l3_vni` (RFC 9135 symmetric IRB: a MAC+IP's Label2), `EvpnUpdate` (`Full`/`Add`/`Remove`, plus `FullPart` for a `Full` cut by `EvpnUpdate::split()` at `evpn_push_budget()` encoded bytes: `EVPN_PUSH_BYTES` = 4 MiB, or env `NOS_EVPN_PUSH_BYTES` for tests; the generic cutting and receiver staging are `nos_proto::chunk::{split_full, FullStaging}`, shared with `BgpRouteUpdate::frames`; `nos-ribd` and `nos-fdbd` stage `FullPart`s per connection and apply once on the closing `Full`, `EvpnUpdate::absorb`) — `nos-proto` can't depend on `nos-bgp`, so EVPN routes cross the wire structured, never as `bgp::evpn::EvpnNlri`) — `nos-fdbd`'s protocol. `BgpRequest::RedistributeMacs { domain, update }` is the local-MAC push in the other direction. |
| `lldp` | `LldpRequest::GetNeighbors`/`GetStatistics`, `LldpEvent::Neighbors(Vec<LldpNeighbor>)`/`Statistics(Vec<LldpLinkStats>)` (one interface's 802.1AB §9.2.6 counters — frames out/in/in-errors/discarded, TLVs discarded/unrecognized, ageouts, too-many-neighbors drops — backing `show lldp statistics`), plus `LldpNeighbor` (local interface, chassis id, port id, port description, system name/description, enabled capability names, management addresses, seconds until it ages out, and the decoded IEEE 802.1/802.3 org TLVs — `port_vlan_id`, `vlan_names: Vec<LldpVlanName>`, `link_aggregation: Option<LldpLinkAggregation>`, `max_frame_size`, `mac_phy: Option<LldpMacPhy>`; `Default` so tests stay short) — `nos-lldpd`'s neighbor-query protocol, backing `nos-cli`'s `show lldp neighbors`. Chassis/Port IDs are pre-formatted display strings, not the raw 802.1AB subtype/value pair — nothing downstream interprets them. Only one instance exists, so like `lacp` there's no per-instance socket to pick between. |
| `stp` | `StpRequest::GetSummary`, `StpEvent::Summary(StpSummary)` — `nos-stpd`'s status query (`ServiceRef::Stp`, one instance), backing `show spanning-tree` and `GET /v1/spanning-tree`. `StpSummary { enabled, mode, bridge_id, root_id, root_path_cost, root_port, hello_time_secs, max_age_secs, forward_delay_secs, ports: Vec<StpPortInfo>, mst: Option<StpMst>, pvst: Vec<StpInstance> }` (`enabled: false` and no ports when the mode is `disabled`; `pvst` is one tree per domain in `rapid-pvst` (#322, `StpInstance.id` is the VLAN, `StpInstancePort` also carries `inconsistent` and `compat`), served by `show spanning-tree domain` and `GET /v1/spanning-tree/domain/<bd>`; `mst` is set in `mstp`: `StpMst { region_name, revision, digest, max_hops, instances: Vec<StpInstance> }` with `StpInstance { id, vlans, domains, bridge_id, root_id, root_path_cost, root_port, ports: Vec<StpInstancePort { name, role, state, boundary, inconsistent, compat, cost, priority, designated_bridge, designated_port }> }`, instance 0 the CIST — it backs `show spanning-tree instance`/`mst-config` and `GET /v1/spanning-tree/instance/<n>`/`mst-config`); `StpSummary.topology` and each `StpInstance.topology` are `StpTopology { count, last_secs_ago, last_port, last_cause: StpTcCause }` (#323); `StpPortInfo` and `StpInstancePort` also carry `point_to_point`, `counters: StpPortCounters` (RFC 4318 BPDU, TC, migration, invalid and forward-transition counters) and, on the instance port, `edge`; `StpPortInfo { name, role: StpRole, state: StpState, cost, priority, designated_bridge, designated_port, edge, bpdu_guard, bpdu_filter, root_guard, loop_guard, restricted_tcn, root_inconsistent, loop_inconsistent, err_disabled, err_recovery_secs }` (the last ten are the #320 protections: configured, and what holds the port now). Bridge/port ids are pre-formatted strings. `StpRequest::Mcheck { interface }` (802.1Q `mcheck`, `None` = every port) answers `StpEvent::Mcheck { ports }`, the number of ports reached. `StpRequest::ClearErrDisabled { interface }` answers `StpEvent::ErrDisabledCleared { cleared }`. Allowed for `Role::User` and `Role::Restd` only; fields are appended, never reordered. |
| `acl` | `AclRequest::Show { name: Option<String> }`, `AclEvent::Acls(Vec<AclStatus>)` — `nos-acld`'s counter query (`ServiceRef::Acl`, one instance), backing `show acl` and `GET /v1/acl[/{name}]`. `AclStatus { name, default_action, default_packets, default_bytes, levels, filters, attached: Vec<AclAttachment { interface, direction }>, rules: Vec<AclRuleStatus { name, action, dropped, level, packets, bytes }> }`; `dropped` is `shadowed` or `trailing` for a rule the optimiser gave no filter (counters 0). Every ACL of the config is listed, unattached ones with `attached` empty and zero counters; an unknown `name` gives an empty vector. Allowed for `Role::User` and `Role::Restd` only. `AclRequest::ShowFlowspec` -> `AclEvent::Flowspec(Vec<FlowspecRuleStatus { instance, flow, actions, unsupported, packets, bytes }>)` (same roles plus `Role::Bgpd`, which joins it into `show bgp flowspec`'s `dataplane`, #562) backs `GET /v1/flowspec` and the end of `show acl`. `AclRequest::PushFlowspec(FlowspecSet { instance, devices, rules: Vec<FlowRule> })` -> `AclEvent::Ack`, `Role::Bgpd` only: one instance's flow rules as a snapshot (empty clears; `nos-bgpd`'s `acl_push_client` sends `devices` empty and `nos-acld` attaches the instance's `flowspec` devices, #562); `FlowRule { flow, ipv6, components: Vec<FlowComponent>, actions: Vec<FlowRuleAction> }` mirrors `nos-bgp`'s decoded NLRI and actions (#561). |
| `bfd` | `BfdRequest::{Register, Deregister, GetSessions, GetReflector}`, `BfdEvent::{State, Sessions, Reflector}`, `SessionKey`, `BfdState`, `BfdDiag` (RFC 5880 §4.1 codes, kebab-case names) — `nos-bfdd`'s session protocol (`ServiceRef::Bfd`, one instance). `GetSessions` is answered once and is allowed only for `Role::User` (`nos-cli`) and `Role::Restd`. |
| `codec` | `IpcCodec<T>`: framing codec (4-byte LE length prefix + postcard payload). Generic over any `Serialize + DeserializeOwned` type, so it frames the config, broker, RIB, and interface protocols alike. |
