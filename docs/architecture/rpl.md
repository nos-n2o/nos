# Routing policy language (RPL)

Contributor-facing; moved from the root `CLAUDE.md` (#260). Operator view: [docs/README.md](../README.md).


A `BgpPeerGroup`'s `import_policy`/`export_policy` (each an `Option<String>` naming a `PolicyDefinition`, `None` defaulting to `deny-all` — this NOS never leaves a direction unfiltered) reference a small imperative script language, `nos-rpl` (`rpl/`), compiled once by `nos-config` at commit time (rejecting an invalid script before it can be referenced) and again — cached — by each `nos-bgpd` instance that uses it (`bgp/src/policy.rs`'s `PolicyCache`). `nos-rpl` has no NOS-internal dependencies, like `nos-proto`/`nos-tcp-auth`: it exposes a plain `Input`/`BgpInput` shape a consumer adapts its own route type into (`bgp/src/rib.rs`'s `to_policy_input`), and a `Verdict` the consumer applies back onto its own route.

**Language**: Python-style significant indentation, one statement per line. A script is a flat list of statements — `if`/`elif`/`else` (an `if` with no `else`, or any branch not itself terminating, is an ordinary non-terminating statement, not a self-contained policy), `set this.<field> = <expr>` (`local_pref`/`med` numeric; `origin` an `origin.*` literal; `next_hop` an address literal or `self`), `set this.<field> += <expr>`/`-= <expr>` (`local_pref`/`med`, saturating; an unset `med` counts as 0), `this.<field>.add(..)`/`.remove(..)`/`.clear()` (community-list fields only, see below), `this.bgp.as_path.prepend(<asn>[, <count>])` (count 1-16), and the two terminals `accept`/`reject`. `check.rs`'s `check_termination` rejects at compile time any script where some path never reaches a terminal statement, or where a statement follows one that already terminated its block — a policy can never silently fall through.

**As-path regexes** (#667): `BgpInput.as_path_segments` (`nos_rpl::Segment`) lets `vm::render_path` write `AS_SET` as `{..}`, confed sequences as `(..)`, confed sets as `({..})`; `_` is expanded by `expand_underscore` (not inside `[...]`, `\_` literal) to `(?:^|$|[ {}()])`. Empty segments mean one sequence of `as_path`. The flat `as_path` still serves `.length`, `.contains` and `prepend`.

**Fields** (`this.prefix`, `this.bgp.*`) are a fixed table in `schema.rs` (`FieldId`/`FieldType`/`FIELDS`), each either a plain scalar (`this.bgp.origin`, compared with `==`; `this.bgp.local_pref`, settable), `this.bgp.med` (reads as 0 when unset via `Op::LoadMed`, and sees the run's own `set`), the read-only AS accessors `first_as`/`neighbor_as`/`origin_as` (optional ints: only comparable with an integer literal through `Op::OptIntCmp`, unset is false except for `!=`), `this.bgp.as_path.path_length` (`Op::AsPathLen`, RFC 4271 §9.1.2.2: sequence = ASN count, set = 1, confed = 0), and next-hop-style optional addresses (`==`/`!=` via `Op::OptIpEq`, `in <cidr>`/`in <prefix-list>` via `Op::OptIpIn`/`OptIpInList`); the accessors and `path_length` read `vm::effective_segments` (`BgpInput.as_path_segments` plus the script's own `prepend`, never the flat list, so an adapter MUST pass the complete segmented path; `run` debug-asserts it), or a list (`this.bgp.as_path`, `this.bgp.cluster_list`, `this.bgp.communities`/`extended_communities`/`large_communities`) exposing only `.length` and `.contains(..)` for matching — never read as a whole value. `this.prefix in 10.0.0.0/8` and `this.bgp.as_path.contains(65010)` are the basic prefix/as-path matching idioms, extended by `this.bgp.as_path.matches("^65001_")` and `this.bgp.as_path in NAME` (regex against the ASNs rendered space-separated, `_` = start/end/space boundary; a named `as-path-list` matches if ANY pattern does); neighbor context is `this.bgp.peer` (address, compared with `==`/`!=` against a literal — like `next_hop`/`router_id`, which are unreadable except that way) and `this.bgp.peer_as` (int; both are unset/0 for a locally-redistributed route); the three community fields extend the same `.contains(..)` idiom with `AA:NN` (standard, RFC 1997), `type:subtype:value` (extended, RFC 4360), and `ga:ld1:ld2` (large, RFC 8092) colon-separated literals — disambiguated by the target field's type, not the literal's own shape, and requiring no lexer support beyond the `:` token the block-syntax colon already uses (a colon literal's `Int` parts are only ever consumed by `parse_atom` when immediately followed by another `Int`, which a block-starting colon, always followed by a newline, never is). Community fields are also regex-matchable: `.matches("^65000:")` / `.remove_matching("^65000:")` (exactly one string literal; `Op::CommunityMatches`/`Op::CommunityRemoveMatching`, reusing `AsPathRegexes` incl. `_` expansion) run against each value rendered as decimal `AA:NN` / `type:subtype:value` / `ga:ld1:ld2` — `_` can only match at the text's start/end, so `_65000:_` never matches (prefer `^65000:`); `remove_matching` checks immutably first so a non-matching run never clones the list; named regex lists for communities are out of scope. Community fields are the only list fields that are also mutable: `.add(65000:100)`/`.remove(65000:100)` add/remove one value, `.clear()` empties the list — real policy wants incremental edits, not whole-list literal replacement, so there's no list-value syntax at all.

**Execution model**: `codegen.rs` compiles the AST straight to bytecode (`vm::Op`) in one pass that doubles as type-checking — no separate type-check pass, since emission needs the same field-resolution work a type-checker would. `vm::run` executes against a fixed-size operand stack (`MAX_STACK_DEPTH`, compile-time-bounded, no heap allocation on the hot path — this runs once per route, per peer, per update) plus a handful of mutable locals seeded from the input and threaded through execution exactly like ordinary variables (`this.bgp.local_pref` read after a `set` sees the new value in the same pass) — `cur_local_pref`/`cur_med` for the two settable scalars, and `cur_communities`/`cur_extended_communities`/`cur_large_communities` (each a `Cow` over the input's borrowed slice — the one deliberate exception to "no heap allocation," since a script that actually calls `.add`/`.remove`/`.clear` needs to hand back an owned list through `Verdict::Accept`, but `Cow::to_mut()` only clones on that first actual write, and a `Reject` verdict never pays for it at all). `Verdict::Accept` always carries the current value of every mutable field, whether or not the script touched it — same guarantee for the three community lists as for `local_pref`/`med`.

**VPN hooks (#582)**: `BgpInput.rd: Option<u64>` is the VPN route's Route Distinguisher (types 0/1/2 start with a zero octet, so it is also a non-negative `i64`; `None` for any other route), read-only as `this.bgp.rd` (`FieldType::OptionalRd`, only `==`/`!=` against `rd(..)`, via `Op::OptRdEq`). The parser turns `rt(..)`/`soo(..)`/`rd(..)` into `ExprKind::ExtLit` already encoded (the same type choice as `nos_proto::evpn_id::parse_rt`/`parse_rd`: `nos-rpl` stays dependency-free and `bgp/src/vpn/ext_comm.rs` pins the equality); `rt`/`soo` are extended-community literals for `.contains`/`.add`/`.remove`, `rd` is not a community. `bgp/src/rib.rs`'s `to_policy_input` takes the RD argument. Import policy runs when a VPN path is stored (before import by RT), export policy on every path sent (after ribd attached RTs and SoO); `Verdict` is unchanged, edits ride `extended_communities`.

**Built-in system policies**: `ACCEPT_ALL`/`DENY_ALL` (`accept-all`/`deny-all`) are compiled once (`LazyLock`) from `"accept\n"`/`"reject\n"` rather than stored as `PolicyDefinition` config entries — nothing to edit, nothing to delete, and every peer-group's unset `import_policy`/`export_policy` resolves to `deny-all`.

**Named community aliases, community groups, and prefix lists**: three more top-level config sections — `AsPathList` (a named set of as-path regexes, compiled into `Op::AsPathMatches`), `CommunityAlias` (one name → one community literal), `CommunityGroup` (a flat, named set of alias names and/or inline literals — `.contains(..)` matches if ANY member matches; `.add(..)`/`.remove(..)` apply to every member), and `PrefixList` (a named set of prefix entries, each either a bare CIDR — **exact match only**, deliberately diverging from `this.prefix in <cidr>`'s own containment/orlonger semantics — or `<cidr> range(<min>,<max>)`, matching any prefix contained within that CIDR whose own length falls in `[min, max]`) — referenced by bare identifier anywhere a literal is valid today (`this.bgp.communities.contains(NAME)`, `.add(NAME)`, `.remove(NAME)`, `this.prefix in NAME`). `nos-rpl` itself stays dependency-free: `nos_rpl::compile` takes a `Symbols` table (name → resolved value(s)) that the caller — `nos-config`'s commit-time validation and each `nos-bgpd`'s `PolicyCache` alike — builds from its own `community_aliases`/`community_groups`/`prefix_lists` config sections, the same adapter pattern as `Input`/`to_policy_input`. An undefined name surfaces as an ordinary `CompileError`, exactly like any other compile error — this is the entire cross-reference-validation story for the three sections, no separate reference-checking pass. `Verdict::Accept` additionally carries `edits: Edits` — `as_path` (`Some` only if the script prepended), `origin` and `next_hop: NextHopSet` — each "unchanged" by default so an untouched attribute costs nothing; `nos-bgpd`'s `apply_verdict` writes them back (import/redistribute) and `build_advertisement` lets a policy next hop override `next_hop`'s mode (export). `nos-bgpd` learns each peer's ASN via `BgpRib::set_peer_asn` (from the OPEN) for `peer_as`. Groups compile to N sequential existing ops (`ListContainsCommunity`×N OR'd together, or `CommunityAdd`/`CommunityRemove`×N) rather than a new opcode, since membership is flat and small; prefix-list matching is a new `Op::PrefixInList` opcode, since exact/range-within-CIDR matching has no existing equivalent.

**BGP roles and OTC (#872)**: `BgpInput.local_role`/`remote_role: Option<Role>` (`nos_rpl::Role`, same values as the RFC 9234 capability) and `otc: Option<u32>` are read-only `this.bgp.{local_role,remote_role,otc}`. The roles are `FieldType::OptionalEnum("role")`, compared only with `==`/`!=` to `role.*` via `Op::OptEnumEq` (unset is false, `!=` is its `Not`); `otc` reuses `Op::OptIntCmp`. `nos-bgpd` fills them through `PolicyPeer` for unicast import and export only (remote role only when negotiated, from `BgpRib::set_peer_role_negotiated`); `otc` is the post-ingress `RibRoute.otc`.

**RPKI**: `this.bgp.validation_state` (read-only, compared with `==`/`!=` against `rpki.valid`/`rpki.invalid`/`rpki.not_found`, the same enum-literal form as `origin.*`) is RFC 6811 origin validation, computed by `nos-bgpd` before import policy runs against the VRPs its RTR client fetched (see `docs/protocols/bgp-internals.md`'s "RPKI origin validation"); `CompiledPolicy::reads_validation_state()` tells `nos-bgpd` which peers to route-refresh when the VRPs change. An iBGP peer-group's `announce_rpki_state` exchanges the state as the RFC 8097 extended community, used on receipt only while the instance has no VRPs (#162).

**Explicitly out of scope (v1)**: any capability beyond `bgp` (e.g. a future `this.static.*` for a different attach point) — `nos-rpl`'s two attach points (BGP import/export) both guarantee the exact same `Input` shape today, so there's no per-attach-point capability variation to model yet.

**Policy chaining (#870)**: `call NAME` is inlined at codegen, with no VM change. `Symbols.policies` lends `(name, source)` pairs (built by `nos-proto`'s `valid_source`, `nos-bgp`'s `PolicyCache::resync`, the OSPF daemons and the CLI); `Codegen::compile_call` parses and termination-checks the callee once (cached), compiles it in place, and an `accept` inside a callee frame is an `Op::Jump` patched to the code after the callee while `reject` stays `Op::Reject`. `StmtKind::Call` is non-terminating in `check.rs`. Limits: `MAX_CALL_DEPTH` 8 (codegen), `MAX_CODE_OPS` 65 536 (`vm.rs`, bounds the k^depth fan-out), cycles are compile errors. `unconditional_next_hop` stops at a call. `PolicyCache::resync` recompiles every policy on each diff, so a callee edit reaches callers with no dependency tracking; commit validation checks each `PolicyDefinition` against the whole config.

**Resource limits (#628)**
- Source is capped at `MAX_SOURCE_LEN` (16 KiB), checked by `compile`, `unconditional_next_hop`, called-policy compilation and `PolicyDefinition.source` validation.
- AST depth is capped at 64 in `parser.rs` (`MAX_DEPTH`): statement-suite nesting plus expression depth. Left-associative chains (`a or a or ...`, `+`) count too, since they build a left-deep tree that `check`, `codegen` and `Drop` recurse over.
- Parser recursion (suites, `not`, parentheses) is capped at 64 separately, so deep input fails with `nesting deeper than 64` before it can overflow the stack.
